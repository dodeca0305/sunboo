# ロードマップの公式リンク・提出先案内の保護（2026-11-06）

## 問題と今回の修正

架空会社23の償却資産申告から、旧渋谷区URL `https://www.city.shibuya.tokyo.jp/kurashi/zeikin/hojin/` へ遷移し404になった。旧窓口マスターは確認済みの状態のままで、償却資産申告にも共通のmunicipal_tax窓口を当てはめていた。会社の本店所在地だけでは、資産所在地別の提出先は確定できない。

本修正はロードマップの共通データに、次の表示上の保護を追加する。既存の税務判定、手続きの出現・期限、税額・保存処理は変更しない。

- 東京23区に本店がある会社の償却資産申告は、区役所名を提出先として確定表示せず「提出先の確認が必要です」とする。23区内の資産は資産所在区の都税事務所、23区外は所在市町村の案内を確認する旨を短く示す。東京都の償却資産の説明（23区内資産向け）へ案内する。本店が23区でも全資産が23区内だとは推測しない。
- 同じ旧区役所URLが使われていた法人市民税申告も、東京23区の市町村民税相当分は法人都民税として扱われる旨の東京都公式説明へ案内し、区役所を個別の申告先として確定しない。既存の申告候補や税額欄は削除/統合せず、税務判定・二重計上防止の新しいロジックへ拡大しない。
- 実際に404を確認した旧URLは、www有無・クエリ/フラグメント・末尾スラッシュを正規化してロードマップの窓口リンク/補足リンクから除外する。DBのstatusがokでも再び出さない。brokenの公式URLと同じURLをwebsite/fallback欄から再採用する経路も止める。別の有効な候補は既存の優先順で保持する。
- 東京23区外の既存経路、札幌/福岡/北九州の提出先Resolverの切替対象は変更しない。既知の誤った渋谷区URLが償却資産に渡る場合は、所在地情報が欠けても誤案内を停止する。

## 影響範囲と段階分け

buildAnnualRoadmapの表示データに保護を適用し、会社ホームの参照元・管理ロードマップ・共有ロードマップ・一般の会社プロフィールからのロードマップに同じ状態を渡す。共通の提出先変換からExcel/PDFにも要確認表示・正しい説明URL・注意書きを渡す。共有へ新たな個別情報を公開しない。

一般の診断結果 `/result` は独立した古い窓口一覧/手続き表示を持ち、今回の年間ロードマップとは別経路である。この診断結果の窓口一覧や管理用窓口一覧、DBマスターの全面的な訂正、全国URLの全件検査は今回変更していない。これらには旧リンクが残り得るため、別段階の残課題とする。今回の修正で全画面・全自治体の提出先が検証済みになったとは扱わない。

## DBと本番制限

DB構造・関数・権限・マイグレーション・共用窓口マスターを変更しない。既存SQLを一括適用しない。旧窓口マスターのok表示そのものは未訂正であり、アプリの該当経路で保護する。共用マスターを変更する場合は他手続きへの影響、対象行、変更前定義と復旧を準備し、本番読み取り制限に従って別途確認する。

本番は架空会社23の画面・配信の読み取りのみ。申告実行・保存・リンク発行/失効・実顧客のデータ変更はしない。復旧は今回のアプリ差分を戻すだけで、DB復旧は不要。過去に出力したPDF/Excelの内容は自動では修正されないため、必要なものは再出力する。
