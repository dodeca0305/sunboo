# 初期版の試用手順

完了判定・配信先・実行結果は段階別点検記録と初期版完成基準資料を参照。

2026-11-04に、合成データでの通し受入、PR #157/158の本番反映、本人ログイン後の架空会社23の7画面読み取りと業務データの前後一致まで確認した。初期版の試用受入は完了。以下の制限を理解したうえで、管理者伴走で試用する。

管理者が伴走する初期版。自動申告・納付、専門家の判断、契約/課金、個人への担当者割当は行わない。今回の本番確認は架空会社23の読み取りだけとし、以下の登録/保存/共有リンク発行はローカルの合成データで検証する。

1. 顧問先一覧から会社名・所在地・法人種別・決算月を入力して登録する。通信結果が不明なら入力を変えて再登録せず「登録結果を確認」を使う。再読み込み後も前回要求を確認し、登録が見つからないと確認できたときだけ同じ要求IDで明示的に再試行する。
2. 会社プロフィールを入力する。会社本体とプロフィールは一括保存される。保存結果が不明なら「保存結果を確認」で再取得し、未保存と確認した後に同じ内容を明示的に再試行する。同時編集では古い入力を上書きせず停止する。未登録と取得失敗を区別し、取得失敗中は入力/保存を止める。税務・労務の設定は事実に基づいて確認する。金額0は実際に0と確認した場合だけ入力する。
3. 決算実績は必要な対象年度の情報を入力する。未登録はチェックに問題がないという意味ではない。既存の税務チェックは `TI_TAX_001`（直近実績の法人税申告の基本提出時期）1種類。2023年4月1日以降の事業年度末・必要な申告日・清算特則の該当有無・有効な根拠ルールを確認する。延長等は個別確認が必要で、税務全般や税額計算を網羅しない。
4. ホーム/年間ロードマップで、手続き候補・推奨・要確認を確認する。理由、担当役割の目安（担当者名は未設定）、期限、完了条件、公式の実行先を確認する。情報不足や取得不能なら依存する予定/推奨/集計は保留される。
5. 該当要否を確認し、必要な提出・納付等を行って控え/対応記録を保存してから、対応状況を更新する。「完了」はSUNBOO上の記録であり、行政機関の受付確認や実際の手続き実行の代わりではない。結果不明時は再取得で確認し、無条件に再送しない。
6. 共有画面で公開範囲と有効期限を確認する。リンクを知る人はログインせず閲覧できる。会社/プロフィール/状態の共有に加えて、決算実績の共有は明示的な選択が必要。選択すると金額等も共有先から取得できるため、必要性と相手を確認する。必要な計算入力を共有しないリンクでは、予定は保留される。リンク発行・失効の結果が不明なら再取得で確認する。
7. 共有ページで案内と状態を確認する。編集・保存操作はない。期限切れ/無効リンクと通信障害を区別する。不要なリンクを失効する。

通常の空設定・0件と、取得不能は区別する。共有リンクを本番で開く操作はアクセス時刻の記録を伴うため、今回の本番読み取り検証には含めない。


## 初期版の制限

- パスワード再設定メールの認証サービス側の送信上限は維持する。依頼は1回にし、同じブラウザーで最新メールを開く。アプリは再送拒否時の先行確認キー保護・再読込/同じサイトの複数タブの再送停止を追加。429では送信制限を表示し、1時間の待機をアプリ側の再依頼目安とする（サービスの正確な解除時刻・成功の保証ではない）。その後も本人が確認して明示的に再依頼するまで送信しない。
- 担当は役割の目安と未設定表示で、個人の担当割当・通知・実際の申告/提出/納付代行はない。
- 書類は登録/準備状態の記録のみで、ファイル添付/内容解析はない。住所変更は未対応。
- 大規模マスターの1000行以上等は未取得を推測せず保留する。予定は既存エンジン一括単位で保留される。
- 登録/保存/税務実行の不明結果は同じタブの保存領域で確認する。タブ終了・保存領域消去・別端末をまたぐ要求一覧共有は未実装。未確定要求がある間に保存領域を消して新規登録し直さない。
- 既存直接API権限や全画面を再監査した版ではない。新しい登録/プロフィール保存経路で検証し、旧タブは再読み込みして利用する。
- 横断整合性チェックは次期計画。代表者個人・関連会社・帳簿/入出金/書類本文・過年度をつなぐ新機能は未実装。


利用者が実操作する際は[試用チェックリスト](INITIAL_TRIAL_USER_CHECKLIST.md)に期待結果・迷った点・改善希望を記入する。チェックリスト作成時点で試用の書き込みは未実施。以後は利用者の試用結果を待ち、新機能を追加しない。横断分析と書類整理連携は次期計画として維持する。
