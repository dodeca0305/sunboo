# ロードマップ・書類：共用読み取りの保護

2026-11-03。起点main `2b57211`（PR #154）、未解決PR0件。ホームPR #151と本番税務実行PR #153は完了済みとして維持する。

## 変更境界

共用loader・診断/ルールエンジン・期限計算・提出先Resolver本体は変更しない。管理用ロードマップ/書類の2呼び出し元だけで、取得結果を検証してから既存 `loadWorkspaceRoadmapContext` の `readInputs` へ渡す。DB構造・関数・権限・マイグレーション変更はない。

`workspacePlanningData` はプロフィール/所在地、決算実績、手続き状態を独立した `loaded` / `unavailable` で保持する。プロフィール/実績はPR #153で検証した厳密な読み取りを再利用する。正常なプロフィールnullと実績空配列は成功として従来の既定値/計算入力を維持し、error/例外/不正行やページ途中の失敗とは分ける。会社本体は正常な不存在だけ404、取得失敗はエラーとフル再読み込み。

`workspacePlanningReadGuard` は既存read guardに重ねた、この2画面専用のwrapper。診断ルール/条件/アクション、手続きと必要書類/公式リンク、旧窓口のjoin、新提出先のルール/管轄/窓口/根拠などを確認する。error/通信例外/null配列/不正な条件・join欠落・重複ID・要求したIDの欠落を、内部で空配列や旧窓口へ退避しても成功扱いしない。元client・ホーム/共有/税務実行の契約は変更しない。書き込みとRPCは拒否する。

## 依存関係と部分表示

| 情報 | 正常な部分を残す範囲 | 取得不能時に保留/停止するもの |
| --- | --- | --- |
| プロフィール/所在地・実績 | それぞれ正常な従業員数/決算月・実績件数を表示 | どちらか取得不能なら予定生成を呼ばず、予定・推奨・総合集計・出力を保留 |
| 診断ルール・手続き・窓口・提出先 | 正常な会社情報/実績/状態/納税予定の登録記録、書類登録状況を残す | 既存エンジンが一括生成する予定全体と依存する必要書類算出を保留。未取得から一部の予定だけを完全と推測しない |
| 手続き状態 | 予定の期限・提出先は状態に依存しないため、他の取得が成功すれば表示を維持 | 未着手と表示せず状態変更を停止。完了状態に依存する必要書類算出とExcel/PDFを保留 |
| 納税予定 | 正常な予定・状態と、取得済み納税予定の記録件数を残す | 未取得金額を0へ置換せず入力/保存・Excel/PDFを停止。予定が0件/決算月未登録の場合もエラー/再読み込みを隠さない |
| 書類登録/準備状況 | 共用contextが失敗しても、両状態元を取得できた代表書類の記録/件数を維持 | 従来どおり片方の状態取得失敗で編集を停止。必要書類を算出できていれば読み取りのみ表示し、準備状態を未準備にしない |
| 必要書類算出 | 代表書類の正常な登録状況と独立 | `null` は算出保留、`[]` だけが正常な空。取得失敗を「未準備の必須書類なし」に変えない |

正常に取得できた決算月がnullの場合は、通信障害ではなく未登録として登録案内を出し、必要書類は算出保留とする。状態取得失敗等が重なった場合はエラー/再読み込みも維持する。

書類・手続き状態・納税予定の既存の保存処理/結果不明時の再送停止は変更しない。書類は代表書類と派生した必要書類を分け、派生分が取得不能でも独立して取得した代表書類の記録を空にしない。
