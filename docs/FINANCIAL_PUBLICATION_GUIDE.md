# 決算公告の確認案内と未確認時の保存停止

2026-11-11。試用で「決算公告は実施しましたか」が分からないとの指摘を受け、「この決算の内容を公開しましたか？」と「何を確認する？」に変更。管理用とローカル保存用で同じ部品を使う。説明は初期折り畳み。公開済み/未公開/わからないを選ぶ形式とし、税務署への申告とは別の手続きであること、対象決算期の官報・新聞の控え/会社の公告ページを確認することを案内する。掲載が見つからないだけで未実施とは推定しない。

根拠：[中小機構J-Net21の決算公告の説明](https://j-net21.smrj.go.jp/solution/qa/accounting/Q0536.html)。原文の費用や期限の数値は転載しない。法務省の電子公告制度ページは検索結果で確認したが直接取得は403のため、画面は取得できた中小機構の説明へリンクする。SUNBOOから公告の申込みや公開は行わず、掲載の適法性を自動判定しない。

## 保存範囲

既存DBの financial_statement_published はNOT NULLのboolean。既存の型、読取検証、共有RPCの戻り値もbooleanのまま。新しい保存値・DB変更は追加しない。「わからない・確認する」はフォーム内だけの状態とし、株式会社でこの状態の間は決算実績全体の保存を、要求記録作成/API/localStorage保存より前に停止する。新規は未確認から開始し、既存編集は保存済みtrue/falseを維持する。既存falseを未確認だったと推測して書き換えない。確認済みの選択だけが既存booleanを更新する。

未確認の下書きを保存したり、ブラウザー再読み込み後に復元する機能は今回追加しない。確認が取れるまでは他の入力内容も保存できない。非表示条件（株式会社以外）は既存データと保存動作を維持する。取得失敗の編集停止、保存結果不明時の再送停止/再取得を維持。判定・期限計算、DB/関数/権限、課金は変更なし。

## 試験・復旧

合成の期間入力試験に、案内のキーボード開閉/公式リンク/375px、開閉で値・書込回数不変、新規未確認/既知の値から未確認に戻した時の送信停止、ローカル保存のtrue/false再編集・既存値保護を追加。既存の読取/保存失敗と応答喪失の試験も維持。決算実績安全性試験は新規保存の前に明示選択し、株式会社以外の非表示項目保持も確認する。確定結果はBusiness側記録へ追記する。

本番は架空会社23で表示・案内開閉のみ。値の選択・入力・保存は行わない。復旧は今回のアプリ変更を戻して通常配信。SQL適用・データ復元は不要。

残課題：利用者の理解度評価、未確認の下書きの永続保存（必要なら別途DB変更案を提示）、既存falseの確認履歴は不明、他の専門用語の案内、書込試用環境の同期、広範囲ブラウザー試験の既知課題、旧共有Gitの不正ref修復。横断分析・書類整理連携は次期計画のまま。


検証確定：全1,005テスト成功、Lintエラー0/既存Growth警告1、Webpackビルド/型検査成功。期間入力画面の合成試験は両画面/375px/案内開閉/未確認時のAPI・要求記録・localStorage書込停止/既存値保護/true・false再編集を確認（合成API書込3、本番呼出/ブラウザー例外0）。決算実績の障害・復旧試験も専用ポート3136で全体成功。会社/プロフィール/地域/実績のerror・例外・不正応答、正常未登録、非表示項目保持、保存拒否/応答喪失/再読み込み後の確認/削除復旧を確認した。

試験中の中断：初回の連続再読み込みはNextの描画エラー/待機時間切れで停止、再試験も待機時間切れ。比較用mainは全体成功。比較用と同じポートを使った後続試験ではEADDRINUSEで別の旧画面を読んでいたことを確認したため、その結果は採用せず、使用中ポートを拒否する事前確認とTAX_RETURN_TEST_PORTの指定を追加。独立ポートの全体再検証で成功した。初期中断を成功として数えない。以前からの広範囲ホーム等のブラウザー試験課題を解決済みとは扱わない。
