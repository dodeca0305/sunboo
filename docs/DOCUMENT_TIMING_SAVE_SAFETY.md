# 書類の対象時期と保存保護（2026-11-06）

## 対応範囲

PR #170の人数・役員変更日の説明は維持し、承認済みの書類時期の保存だけを追加する。定款は作成・変更日、登記簿謄本は発行日、申告書・納付書は対象期間の開始・終了日を、原本を見て入力する。未記録は空欄で保存可能。現在年・決算月・updated_atから日付を補完しない。

書類行の「状態・対象期間/発行日を編集する」を開き、登録状況と日付を確認して「○○を保存する」で一緒に保存する。選択だけでは送信しない。登録済み件数は確認できた保存結果に合わせて更新する。種類ごとの現在の1件だけを扱い、過年度/複数版、添付、提出証明、自動期限判定、共有への日付公開は対象外。

## 保存保護

- 編集用の共用取得だけを拡張。状態・任意日付・正確な更新時刻を確認できない場合は、従来どおり全編集を止めて再読込を表示する。正常0件は空欄で入力可能。
- 状態と日付3項目は1行のINSERT/UPDATEで原子的に保存。既存行は会社・書類種類・元のupdated_at（6桁小数を文字列のまま保持）と元の状態/日付すべてで条件更新する。新規行はINSERTのみで、主キー衝突を上書きしない。0行や応答不正を成功扱いしない。
- 時刻だけでなく元の全値も比較する。ローカルPGliteでは同じミリ秒の更新が生じるため、同一時刻でも別内容へ更新した後の送信を拒否できるようにした。DBのトリガー/関数は変更しない。
- 保存前に利用者ID・会社・書類種類ごとの送信予定/元の値をlocalStorageへ記録し、Web Locksで同じブラウザー内の送信を排他制御する。別タブの記録変更で編集を停止。記録が作れない場合は送信しない。ログイン利用者も送信・復旧の都度確認する。
- 保存失敗/応答喪失は成功とせず、その画面の編集を停止。再読み込み後も保存確認記録を読み、認証付きの新規取得で結果を照合する。保存予定と一致なら確認済み、元のままなら同一内容を本人が明示再試行、別内容なら競合停止。自動再送しない。遅れて到着した旧要求も元の値/版の比較と主キーで保護する。
- 再取得失敗でも未登録に変換しない。権限変更・別会社の応答・不正な期間/版も保留する。日付だけ・状態だけを編集しても、残りの確認済み値を消さない。元の記録が別会社/利用者のものなら復旧要求として受け付けない。
