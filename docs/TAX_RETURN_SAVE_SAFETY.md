# 決算実績の取得・保存保護

2026-11-02、起点main `a82246d`（PR #148）。最新mainとオープンPR0件を確認し、点検記録の決算実績未対応を照合して着手。既存の納税予定・手続き状態・管理用ルール・窓口保護は変更しない。

## 取得失敗と正常未登録

会社本体の正常な不存在だけを404とする。会社/決算実績/会社プロフィールと所在地補助取得のerror・例外は、専用のエラーと「再読み込み」を表示し、実績一覧・登録/編集/削除フォームを渡さない。「実績なし」や金額0を表示しない。再読み込みはフルリロードし、古い事前読込結果を使わない。

決算実績は会社IDで絞り、全ページ・全行のID/会社/決算日/日時/各列/金額構造を検証。null配列・不正行・重複ID/決算日は取得不可。正常な0行だけが「未登録」で入力可能。未入力の金額null、正確な0、概算範囲、金額オブジェクト内の未入力を区別して保持する。型/日付/金額を勝手に補正しない。

会社プロフィールは既存の取得失敗保護loaderを再利用し、決算実績で使う従業員数/消費税/インボイス状態も検証。プロフィールの正常未登録は従来の既定値で入力可能。取得失敗は従業員0のプロフィールとして扱わず、全編集を止める。法人種別は取得確認済みの会社本体を使う。

株式会社の決算公告、従業員がいる会社の源泉税実績という既存の表示条件は維持。正しく取得したプロフィールの条件で欄が非表示になっても、既存実績のその値を既定値へ戻さず保持する。プロフィールとの不一致警告は確認済みの保存応答後のみ表示する。

## 保存・削除と結果不明

新規はinsert、編集/削除は会社ID・行ID・読み込み時updated_atで絞る1行の要求。返却行の全内容を検証し、保存は送信payloadとの全項目一致、削除も同一会社/IDの削除行を確認してから表示を変える。楽観的な削除表示は廃止する。0行更新/削除・不正応答も成功扱いにしない。

送信前に会社別sessionStorageへ保存意図（操作種別、ID、送信内容）を保持。保存中/削除中/結果不明は全変更を停止し、同一描画の連打もrefで抑止する。例外でも処理中表示を解除するが、結果不明の記録は消さず再読み込み後も再送を止める。記録を確保できない場合は送信自体をしない。

「保存結果を確認」では会社・プロフィール・全決算実績を再取得。いずれかが取得できなければ停止維持。既存編集はID、新規は会社内の決算日一意キーと全送信項目、削除は同一IDの不存在で結果を確認する。一致した場合のみ確認メッセージ。不一致なら現在の登録内容を表示し、保存成功と報告せず、最新プロフィール/実績から手動操作を再開する。無条件の再送はしない。

## DB変更不要の根拠

現行本番メタデータで `UNIQUE(company_id,fiscal_year_end_date)` とupdated_at更新トリガーを確認済み。1要求が1行の変更で完結し、既存の一意制約と更新時刻を利用できるため、新規関数/テーブル/列/権限変更は不要。マイグレーションも既存SQL適用も行わない。

## 本番確認と復元

指定の専用架空会社ID 23の名称を照合し、全決算実績・会社プロフィール・会社本体を事前保存する。既存実績のない試験用決算日だけを選び、新規作成→同じ試験行の編集→削除をUIから確認し、各結果をDBから読み戻す。未入力nullと明示的0も照合する。ブラウザの書き込みは同じ会社・試験決算日・新規試験ID・更新時刻条件だけを許可し、他の要求は遮断する。
