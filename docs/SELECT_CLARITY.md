# 選択欄の目印・納付回数の言葉（P05/P06、2026-11-05）

PR #168で次の入力と不足を案内した後、共通の選択欄と納付回数の表示を改善する。表現・操作の見つけやすさだけを変更し、値・判定・期限・保存・権限は変えない。

## 選択欄

既存の.form-select/.form-inputは標準の矢印をappearance:noneで隠していた。select要素だけに共通の右下向き矢印と文字の余白を設け、決算月・会社区分・年度・書類/手続きの状態などで選べることを示す。テキスト欄には矢印を出さず、複数選択/listboxも対象外とする。/startで別に描いていた3つの矢印は共通表示へ統一して重複を防ぐ。

独自のドロップダウンへ置き換えず、標準selectを維持する。disabledは操作不可のまま。強制配色では標準の見た目へ戻す。新しいキーボードイベント処理は設けない。

## 表現

会社管理と一般プロフィール、決算実績の照合表示で、納付回数の表示を共通化する。

- 源泉所得税を納める回数
- 住民税（給与から天引きする分）を納める回数
- 毎月納める / 年2回まとめて納める / わからない・未確認

源泉所得税の年2回は「納期の特例」、住民税の年2回は「自治体の承認済み」を選択肢と説明に残す。税務署への申請による特例の利用と、市区町村への申請承認は別と明示する。自動選択や従業員数だけでの承認判定はしない。unset/unknown、special_exception/special、noneを同じ値に変換しない。

根拠の確認：[国税庁・源泉所得税の納期の特例](https://www.nta.go.jp/taxes/tetsuzuki/shinsei/annai/gensen/annai/1648_14.htm)、[国税庁・承認のみなし等](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2505.htm)、[東京都・個人住民税と特別徴収](https://www.tax.metro.tokyo.lg.jp/kazei/life/kojin_ju/tokubetsu/about)。本変更で期限計算や新たな税務基準は実装しない。

## 検証・限界

全945テスト、Lintエラー0（既存Growth警告1）、Webpack本番ビルド/型確認成功。合成画面で会社プロフィール・年度・書類・/startの選択欄、入力欄には矢印なし、重複矢印なし、Tab/Shift+Tab移動、選択変更、375px幅、強制配色、一般プロフィールの共通文言を確認。PR #168の不足リンク/0/未保存/失敗保護、PR #167の非対象税額入力なし/集計保留・復旧も同じ画面試験で回帰成功。

合成PGliteの登録から共有までの通し試験・保存失敗/応答喪失/再読み込み後の確認が成功。年2回を選んでも、DBには国税special_exception・地方税specialが別々に保存されることを確認。保存結果不明の間はselectもdisabledのまま。実顧客や本番データで障害試験はしない。

このMacのheadless環境では、未装飾の標準selectでもArrowDown→Enterが選択確定にならず、フォーム送信となった。比較で本変更固有の差は検出していない。Tab移動と選択値の変更は成功したが、OSの選択メニューを含む矢印キーでの確定は自動試験だけでは検証済みと扱わない。標準selectの処理を上書きして試験だけを通す対応は行わない。

PR/main CI・本番配信の確定値と、架空会社23の読み取り結果はPRとBusiness側の最終記録へ残す。本番で入力・保存・状態変更・共有発行・税務実行はしない。DB/関数/権限/新規課金なし。
