# 税金の確認結果：読む順番と色分け

2026-11-08。main 11e24f9（PR #177）と点検記録、オープンPR 0件を確認して着手。

## 目的と範囲

利用者の「読みたいと思わない」「早くするべきこと、次にする事の順」「色も考えて分けてほしい」という試用結果に対応する。新機能ではなく、既存の会社別税金の確認結果の表示整理。ホーム・一般診断・共有・ロードマップへ一律に展開しない。担当選択（PR #177）を再実装しない。

## 表示

- 既存結果を先に表示し、新規チェックの説明・実行フォームを下へ移動。対象の短い説明は常時表示し、必要入力・詳細・実行は開いたときに表示する。
- 未対応の要確認で既存重要度critical/errorを「先に確認すること」（赤）、判定不能を「まず情報を確認すること」（オレンジ）、その他の要確認を「次にすること」（青）へ分類。対応済み（緑）と対象外（グレー）を区別する。
- これは読む順番のみ。基準日から期限を推測せず、「申告・納付の期限順ではありません」と表示する。対象外は問題なし・完了へ言い換えない。
- 不足情報の確認と担当者・税理士への相談という短い行動を先に表示する。理由・内部コード・版・評価日時・対応記録の操作はdetails内へ。装飾アイコン・UNKNOWN/REVIEW等の見出しを削減する。
- 正常0件は灰色で表示し、「税務上の問題なし」と見せない。取得失敗時は従来のエラーと再読み込みを維持する。
- 実行要求の結果不明・保存用記録の読み取り失敗・チェック一覧の取得失敗と再読み込みは、実行詳細を閉じても表示。未解決実行がある間は新規実行を無効にする既存条件を維持する。

色は利用者全員に同じ心理効果を保証するものではない。UIでの慣習と注意の強弱を用い、淡い背景・濃い文字・見出し・順序を組み合わせる。色だけに意味を依存しない。既存CLAUDE.mdのモノクロ方針より、今回の利用者の明示的な色分け指示を優先する。

参考：[色の意味の個人差と試用確認](https://www.nngroup.com/articles/color-enhance-design/)、[色だけに依存しない表示](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)。
