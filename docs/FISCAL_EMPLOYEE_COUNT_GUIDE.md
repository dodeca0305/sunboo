# 決算日の従業員数の確認案内

2026-11-11。利用者が「パートやアルバイト、役員も含めるのかわからない」と指摘し、短い表で数える範囲を明示する案へ「行こう」と回答。最新main 523fc91/未解決PR0件を確認し、管理用・ローカル保存用の同じ入力欄を共通部品にした。

見出しは「決算日の従業員数（任意）」、常時表示は「パート・アルバイトを含みます。不明なら空欄で保存できます。」だけ。「誰を数える？」は初期閉じで、上で入力した決算日に直接雇用していた人を1人ずつ数えること、役員だけの人は含めないこと、兼務役員/派遣/出向は担当者に確認することを短い表で示す。正社員3人＋パート2人なら5人、勤務時間による換算をしない例を添える。判断できない人数を0で埋めるよう促さない。

## 目的と根拠の限界

既存の会社プロフィールのEmployeeCountHelpは、直接雇用するパート/アルバイトも1人ずつ数え、兼務役員/派遣/出向は確認する案内を持つ。今回は決算日の記録欄に同じ方向の案内を追加する。会社プロフィールそのものの表示は変更しない。

参考：[総務省統計局の経済センサス用語解説](https://www.stat.go.jp/data/e-census/2019/yougo.html)。有給役員と雇用者の区別、役員が職員を兼ねる場合などを確認した。ただし統計の「従業者」は役員等を含む別の概念であり、今回の入力欄は経済センサスへの回答欄ではない。統計の期間条件や制度固有の人数定義をSUNBOOの税務/社会保険判定へ追加しない。画面にも税務・社会保険の人数条件は別に確認すると明記する。

コードの参照先を調査した範囲では、employeeCountAtFiscalYearEndはDB/ローカルの実績記録とタイムラインmetadata、ローカル画面の現在人数との相違案内に使われる。期末人数から個別の税務/社会保険の人数条件を確定する処理は見つからなかった。全制度の人数条件を監査済みとは扱わない。

## 変更範囲・試験・復旧

既存FormattedIntegerInput、value/onChange、既存のnull/0/正数、保存先・変換・データ型を維持。未入力はnullのままで、役員人数の自動加減算や推測はしない。税務判定/期限計算、DB/関数/権限、課金は変更なし。

合成の期間入力画面試験で両画面、375px、初期折り畳み/キーボード開閉、案内開閉による値/書込回数不変を確認する。既存正数、明示0、空欄の保存/再編集、既存の決算公告未確認時の保存停止、取得失敗/復旧、保存拒否・応答喪失後の再取得を含める。確定結果はBusiness側へ追記する。

本番は架空会社23の表示と案内開閉だけ。人数の入力/選択/保存は行わない。復旧はこのアプリ表示変更を戻して通常配信。SQL適用や業務データの復元は不要。
