# 手続きの「完了の目安」

ロードマップの完了条件（長い抽象文）を、短い見出しと2〜3行の非操作リストに置き換えた。
`src/lib/procedureCompletionGuide.ts`（純粋関数、手続きコードだけで分類）と
`src/components/ProcedureCompletionGuide.tsx`（静的表示）。管理/一般/共有は共通の `AnnualRoadmapView` で同じ表示。

| 分類 | コード | 表示 |
| --- | --- | --- |
| 申告のみ | DEPRECIABLE_ASSET_TAX_RETURN | 申告書を提出した／受付完了を確認し、控えを残した |
| 申告＋納付 | CORP_TAX_RETURN、CONSUMPTION_TAX_RETURN、地方税の3申告（県民税・県事業税・市民税） | 申告書を提出し、受付完了を確認した／納める税金がある場合は、支払いを済ませた／提出と支払いの控えを残した |
| 未確認 | 上記以外すべて（SYNTHETIC_TAX、源泉/住民税の天引き、未知コード、情報不足を含む） | 「まず、担当者にこの2つを確認」：この手続きは必要ですか？／何をすれば完了ですか？ |

## 表示：「流れをひと目で」（completion-flow-design）
- 申告のみ／申告＋納付は見出し「提出から完了まで」。番号・箇条書き記号・絵文字・アイコン・カード囲みなし、白黒＋細い下線、既存CSS色のみ。
- 申告のみ：大きい「提出する」「受付を確認する」を余白で横並び（狭幅は縦）。
  申告＋納付：「提出する」「支払いを済ませる」「控えを残す」の3項目。支払いには常時「納める税金がある場合」。
- 各項目はnative `details/summary`（初期閉）。行動見出しと下線付き「確認すること」を押す/Enterで補足を開閉。
  補足は、公式案内に沿う申告書提出／受付完了の確認と控え保管／（納付）納付先と方法は公式案内で確認／提出と支払い両方の控え。
- 保存・チェックボックス・状態更新なし。ガイド内にinput/button/aなし。未確認（未知・源泉等）は従来の2つの質問表示のまま。
- ヘルパーは `steps`（title/condition/note）を追加しただけ。`lines` とコード分類は不変。
- 採用しなかった「一つずつ見る」案（タブ/stepper）は足していない。

## 変えないこと
- チェックボックス・自動完了・新しい保存・通信・state・DB変更なし。判定基準/期限/既存の `canPlanTaxPayment` は不変。
- 名称・カテゴリから申告/納付を推測しない。未確認は完了を勧めない。
- 既存注記（担当の選択は記録／「完了」は対応状況の記録で受付確認の代わりではない）、支払いとの分離案内、
  提出先・公式ページ、読取失敗/保存結果不明の保護は維持。
- `trialActionGuide` の旧 `completion` 文字列は他の既存試験の契約のため残している（Roadmapでは未使用）。

## 対象範囲と未対応
- 対象：上記6コードの確定分のみ。**全手続きの完了条件を確定したものではない。** 他の手続きは確認の質問にとどめる。
- 未対応：ホームの抽象的な完了条件など、ロードマップ以外の文言。源泉所得税などの納付系コードの個別案内。
- 確認の限界：一般（利用者）画面は共通コンポーネントを使う構造確認のみで、画面そのものは試験していない。
  管理側はローカル合成のロードマップ、公開側は合成共有URL（b×64）で、静的リストの表示とガイド内のinput/button/aが0であることを確認。
