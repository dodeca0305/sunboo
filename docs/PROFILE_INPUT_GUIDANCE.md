# 次に行うこと・会社情報の未入力案内（P02/P03、2026-11-05）

利用者の「最初に何をするか分からない」「必須箇所のマークと未入力を分かりやすく」に対応する表示改善。最新main742884c/PR #167と点検記録を照合し、納付予定の保護を重複実装しない。

## 表示と入力先

ホームの「今日やること」内に、正常取得した決算月・設立日・資本金のうち未入力の項目を表示する。既存の緊急対応候補を先に保ち、続いて「設立日から入力する」等の具体的なボタンを出す。ボタンは会社プロフィールの該当入力欄へ移動・フォーカスする。色だけでなく項目名と「未入力」を示す。優先候補がなく基本情報の不足もない場合は、今後の手続きを確認するボタンを表示する。税務の優先順位や期限は再計算しない。

会社プロフィールでは、既存の保存処理で必要な法人種別・従業員数・会社ステージ・消費税ステータス・インボイス登録状況に「必須」を表示する。決算月・設立日・資本金には「案内に使う情報」を表示し、空欄でも途中保存できることを説明する。一律に保存必須へ変更しない。住所・役員変更予定日は任意、納付サイクル等は「内容を確認」と区別する。

フォームの上に基本情報3項目の未入力数と、各欄へ移動するリンクを表示する。入力内容に応じて不足表示を更新するが、保存済みという意味にはしない。「入力しただけでは保存されない」「選択済みの項目・初期値も実際の会社と合うか確認する」と明記する。補足の薄い文字を濃くして読みやすくする。

## 保護する境界

- 未入力判定は、正常取得した3項目のnullだけ。資本金0・従業員0を未入力扱いにせず、自動入力や日付推測をしない。
- ホームの取得結果はprofile/registeredの構造を保ち、正常取得したprofileだけを入力案内に渡す。取得失敗に不足項目リストを出さず、従来のエラー/再読み込み/集計保留を維持する。
- 保存・応答喪失・同時編集・再読み込み時の保護、保存結果確認後だけの明示的再試行は変更しない。新しい保存API/自動保存なし。
- 共有入力部品のidは省略可能。既存の入力/日付検証/ARIAラベルを変えず、会社フォームでラベルと入力欄を関連付ける。ブロック中にはフォーカスを移さない。
- DB構造/関数/権限/課金、税務判定/期限計算、従業員数の定義や選択肢の意味は変更しない。

## 検証

全945テスト、Lintエラー0・既存Growth警告1。合成UIでホームの不足3項目→決算月へのフォーカス、各不足リンク、入力中の不足表示更新、資本金0/従業員0、未保存の再読込、取得失敗時に不足を捏造せず編集停止、375px幅・キーボード・既存8画面遷移を確認する。

合成PGliteの既存SQLを使う会社登録→プロフィール部分保存→応答喪失→再読込後に保存結果確認→送信前失敗→確認後の明示的再試行→実績→案内→状態更新→共有の通し検証も成功。これは隔離した合成データだけで、本番への税務実行や書き込みは行わない。ホーム各取得・診断内部の障害/復旧と正常0/未登録、ロードマップ/書類/公開共有、PR #167の申告と納付の区別も回帰確認する。

標準CI・配信・本番の確定結果はPRとBusiness側最終記録に残す。本番は架空会社23のホーム/プロフィールを読み取るだけとし、登録/保存/共有操作はしない。DB確認値と本番エラーログも確認する。

## 残課題

未入力一覧はこの3つの基本情報の案内であり、税務判断に必要な情報すべての充足確認ではない。初期値を利用者が確認済みかはDBに保存していない。従業員数の制度別の定義、役員変更日の例示、選択欄の▼と用語統一、書類の対象時期は残課題。利用者が単独で理解できるかの受入は次の試用で確認する。横断分析/書類整理連携は次期計画のまま、新機能は追加しない。
