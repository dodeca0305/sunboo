## 範囲・判定基準

最新main `d3189e7`（PR #141反映済み）を起点に、主要画面の取得→初期値変換→保存先までをコードで追跡した。取得error・nullと正常な未登録が混同され、既存キーへの更新/upsertへ到達するかを確認。本番の既存データを上書きする再現は行っていない。

| 年間ロードマップ | PR #143の納税予定保護を維持。本変更で手続き状態の取得失敗を区別し、状態変更・Excel/PDF出力を停止。正常な0件は操作可能 | 手続き状態の保存確認・応答喪失の再取得・Undoも本変更で保護 |

## 今回の選定理由

会社プロフィールは1回の保存で複数の税務・労務・住所項目をまとめて上書きでき、以後の手続き判定の前提にもなる。利用者の会社別データを直接保護でき、架空会社だけで検証可能なため、今回の1件として優先した。その他の課題を解決済みとは扱わない。

## 修正

- 編集専用 `loadWorkspaceProfileForEditing` を追加。プロフィール・都道府県・市区町村いずれかの取得error/通信例外/不正レスポンスを編集不可として返す。
- プロフィールが正常なnull（まだ行が無い）の場合だけ既定値を使い、新規入力を維持。
- 読み込み失敗時はエラーと再読み込みリンクを表示。フォーム自体を渡さず、空欄・0の保存を防ぐ。
- 正常な既存プロフィールの全項目・保存payloadの変換を維持。DBスキーマ・権限・保存処理は変更しない。
- 共用loaderの読み取り画面への影響を避けるため、変更はプロフィール編集ページの取得処理に限定。
