# 入力・編集画面の取得失敗点検（2026-10-31）

## 範囲・判定基準

最新main `d3189e7`（PR #141反映済み）を起点に、主要画面の取得→初期値変換→保存先までをコードで追跡した。取得error・nullと正常な未登録が混同され、既存キーへの更新/upsertへ到達するかを確認。本番の既存データを上書きする再現は行っていない。

| 画面 | 確認結果 | 今回の対応 |
| --- | --- | --- |
| 会社プロフィール | profile取得errorを無視し、null→既定値（従業員0、資本金・住所null、税務設定等）→会社キーで全項目upsert。無変更保存でも既存値を上書きするおそれ | 修正対象 |
| 売上目標（月次・週次・日次・納税連携） | PR #140のloaderがerror/null/例外をunavailableとしてフォームを停止 | 既存保護を維持 |
| 共有 | PR #141が一覧取得失敗と0件を区別し、発行を停止。結果不明の発行要求も同じ識別子で復旧 | 既存保護を維持 |
| 年間ロードマップ | 納税予定取得失敗でも空Mapを渡し、保存時に未取得額を0としてupsertする経路。手続き状態も取得失敗を空Mapへ変換 | 次候補（未修正） |
| 書類 | 書類/必要書類の取得失敗が空Map→未登録表示となり、状態の変更操作が可能 | 次候補（未修正） |
| 決算実績 | 取得失敗が空の実績一覧として表示される。既存行の編集は読み取れたIDを使い、同じ決算日の新規作成は一意制約エラーを案内するが、取得失敗の表示は不足 | 未修正。空プロフィールによる表示条件への影響も要確認 |
| 手続きマスター編集 | 主レコード取得失敗でnotFoundとなり、空の編集フォームは開かない | 本点検で主レコードを既定値保存する経路なし |
| ルール編集 | 条件・実行内容の副取得失敗を空配列に変換。保存が条件・実行内容の全置換のため、既存条件を失うおそれ | 管理者向けの重要な残課題（未修正） |
| 窓口編集 | 管轄地域の副取得失敗を空の選択値へ変換し、保存時に対応地域を洗い替える経路 | 管理者向けの残課題（未修正） |

## 今回の選定理由

会社プロフィールは1回の保存で複数の税務・労務・住所項目をまとめて上書きでき、以後の手続き判定の前提にもなる。利用者の会社別データを直接保護でき、架空会社だけで検証可能なため、今回の1件として優先した。その他の課題を解決済みとは扱わない。

## 修正

- 編集専用 `loadWorkspaceProfileForEditing` を追加。プロフィール・都道府県・市区町村いずれかの取得error/通信例外/不正レスポンスを編集不可として返す。
- プロフィールが正常なnull（まだ行が無い）の場合だけ既定値を使い、新規入力を維持。
- 読み込み失敗時はエラーと再読み込みリンクを表示。フォーム自体を渡さず、空欄・0の保存を防ぐ。
- 正常な既存プロフィールの全項目・保存payloadの変換を維持。DBスキーマ・権限・保存処理は変更しない。
- 共用loaderの読み取り画面への影響を避けるため、変更はプロフィール編集ページの取得処理に限定。
