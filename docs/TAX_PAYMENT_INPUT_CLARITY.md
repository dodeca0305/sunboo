# 税金の支払予定額の入力案内（2026-11-06）

基点：main 9df349c / PR #173。試用結果の優先順位2「予定税額の欄の場所と用途が分からない」に対応する。新機能・DB変更・税額や期限の計算変更は行わない。

## 表示と操作

管理用ロードマップの上部に「税金の支払予定を記録する」と短い説明を表示し、「金額の入力欄へ」で最初の対象手続きへ移動する。移動先は手続きカードにし、税目と期限を見失わない。カードの入力欄は控えめな青で囲み、「支払う予定額（円）」「この金額を保存」に揃える。納付書/税理士に確認した金額を記録するもので、自動計算・申告・支払いは行わないと明示する。

正常な未登録は空欄で編集可能。空欄の保存ボタンは無効にし、保存処理にも未入力の拒否を追加。クリアしただけで0円へ置換せず、既存の登録金額も削除しない。明示的に入力/保存した0円は「0」と表示する。既存の正の金額・upsertの一意キー・集計方法は維持する。

取得失敗/保存結果不明の場合は、既存の入力・保存停止と再読み込みを維持する。共有・一般向けの閲覧には会社ID付きの金額編集案内を出さない。償却資産申告など申告のみの手続きに金額欄は追加しない。

## 検証

ローカルの合成認証/合成会社900023だけを使用。実API・認証状態ファイル・環境ファイルを参照せず、一般の書込みは遮断する。ブラウザーの税額保存だけを明示的な合成応答で処理し、正常保存、0円、空欄保存停止、既存0円の再取得、取得error/例外/null、保存拒否、保存成功後の応答喪失と再取得、無条件再送0を確認する。ホーム・一般診断・共有・PDF/Excel・申告/納付の区別・375pxの回帰を同時に確認する。

本番は架空会社23の画面の読み取りだけ。金額変更・保存・共有発行・税務実行はしない。結果とCI/配信の確定値はBusiness側記録に残す。

## 復旧と残課題

アプリのみの変更のため、PRのrevert/前の配信への復帰で戻せる。DB復旧は不要。空欄にしても保存済み金額は削除されず、再取得で保存済み額に戻る。金額の削除・自動税額算定は今回追加しない。利用者が入力欄/用途を理解できるかは再試用で確認する。用語全体・電子申告の案内・次期横断分析/書類整理連携は今回の対象外。
