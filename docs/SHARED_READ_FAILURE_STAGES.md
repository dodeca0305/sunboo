## 第1段階：会社ホームの対応

`workspaceHomeData` は各取得元を `loaded(value)` / `unavailable` で保持する。プロフィールと所在地は同じ前提を表すため1単位、実績・状態・書類・日次・月次・連携納税予定はそれぞれ独立。会社本体の取得不能は404へ変換せず、エラーと再読み込みを表示する。正常な不存在だけ404。

正常取得したプロフィールの登録有無/従業員数、実績件数、状態記録件数、要更新書類件数、今月の売上/預金残高の登録値、連携納税予定を表示。未取得の項目は「取得できません」とし、正常な0件/¥0/未登録と区別する。月次が未取得でも日次が正常なら単位未確認の参照値を表示し、誤った売上モデルの編集フォームを出さない。

**総合的な集計・優先順位・推奨行動は、プロフィール・実績・状態・書類・日次・月次・納税予定と税務レビューの取得確認が揃うまで保留する。** 未取得を空に置き換えて進捗/期限/対応不要の結論を出さない。正常な未登録プロフィール・月次の正常な不存在・空の実績/状態/書類/納税予定は取得成功として既存の計算規則に渡す。正常未登録と実際の登録値0は独立カードでも明示する。

read guardはホームに限定したクライアントwrapperで、元のclientを変更しない。各awaitのerror/例外/undefined/null配列/不正な配列・主要join欠落を記録し、内部が失敗を無視して値を返してもホームの派生結果を採用しない。書き込みとRPC実行は拒否する。範囲指定のない1000行以上の応答は打ち切りの可能性があるため、確定集計には使わない（将来の大規模会社向けの自動全ページ化は別途必要）。

税務レビュー要約は未対応レビューと有効チェック評価を別々に保持。片方が未取得でも他方の正常な件数/未評価情報は残す。ただし総合順位の表示は保留する。権限の取得失敗は従来どおり会社削除UIを出さず、他の表示を巻き込まない。

再読み込みはフルリロードするボタン。取得失敗時に以前の事前読込画面から0件を出す経路を避ける。会社ホームの失敗表示で保存・新規登録・API実行を自動で行わない。既存の日次入力は必要な日次/月次を正常取得した場合に限って維持する。

## 検証

- 全681テスト（追加40件）。取得元ごとのerror/例外/null/不正値、正常な空/0/未登録、正常結果の独立保持、内部で握りつぶされたエラーの派生出力拒否、元client不変とread guardの書込拒否を確認。
- 共用context関数の実コードを抽出し、従来呼び出し・状態省略オプション・検証済み入力オプションの3契約を確認。未指定の呼び出し回数・値/計算・出力は維持。
- `npm run test:e2e:home-read-safety`: 認証以外の全業務読み取りは合成し、ブラウザとサーバーの実DB書き込みを遮断。共有の読み取り専用RPCも合成応答のみ。ホームの各取得元・内部のrules/procedures/jurisdictionsにerror/例外/null/不正応答を注入し、対応不要/期限なし/0件へ変換されないこと、正常な別項目の保持、再読み込み復帰、正常空設定と¥0、税務レビューの部分成功を確認。
- ローカルで既存ロードマップ・書類と公開共有の正常表示を確認。ホーム専用プロフィール取得に障害を入れても共有RPCの正常な表示が変わらないことを確認。共有ページ自体の失敗表示を今回修正/検証済みとは扱わない。
- Lint/型チェック/通常ビルド、PR/main CI・本番反映の確定結果はPRと点検記録に記載。本番は専用架空会社ID 23のホームを読み取り、書き込み要求0件と全業務行の不変を確認する。共有リンクの発行・失効、会社データの変更、本番障害注入はしない。

## 第2段階以降に残す範囲

第1段階の反映確認済み: PR #151 / 製品main `fe12461`。PR/main CI成功、架空会社ID 23の本番ホームは6表示と総合表示が正常、業務書き込み要求0件、10種類の会社関連データの前後確認値が一致した。確定結果は[点検記録](INPUT_LOAD_FAILURE_AUDIT.md)を参照。以下は未対応のまま残す。

2. 公開共有のRPC失敗と無効/期限切れの区別、profile/statuses/共有範囲の取得不能、ロードマップ計算失敗を空予定へ変換する表示。匿名/共有権限/トークンの既存試験を含む別PRで対応する。
