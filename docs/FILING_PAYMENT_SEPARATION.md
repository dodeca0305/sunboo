# 申告と納付予定の分離（P08 / 2026-11-05）

## 問題と変更

利用者の「償却資産の予定納税とかあるの？」という指摘を確認した。main90bec3aでも、税務/地方税のカテゴリだけで税額入力を表示し、保存した額を手続きの期限月へ加算していた。償却資産申告の提出日を固定資産税の納付日と扱ってしまう経路だった。

納付を含む既存7コード（WITHHOLDING_TAX、RESIDENT_TAX_WITHHOLDING、CORP_TAX_RETURN、CONSUMPTION_TAX_RETURN、PREFECTURAL_RESIDENT_TAX_RETURN、PREFECTURAL_BUSINESS_TAX_RETURN、MUNICIPAL_RESIDENT_TAX_RETURN）だけに税額の入力・保存を限定する。表示名/カテゴリで推測しない。申告だけの手続き・届出・申請と未知コードは対象外。償却資産申告には、申告と固定資産税の支払いを分け、金額・納付日は自治体の納税通知書で確認する説明を表示する。管理用/一般/公開共有の共通表示を使うが、一般/共有へ編集機能は追加しない。

ホーム・売上目標の読取で既存外部キーに沿って手続きコードも取得する。左結合を使い、参照先が見えない行も消さずに集計を停止する。申告だけの手続きに正の登録額がある場合も、除外して部分合計を返したり0円へ変換したりせず保留する。ホームは他の正常取得部分を残し、売上目標は既存保護に従い編集・保存も止める。正常な空/明示的0/対象の納付額を維持する。

既存行は削除・更新・移動しない。ロードマップの同じ出現回に過去の額があれば保持と集計保留を案内する。ホームは当月の範囲、売上目標は全登録期間を取得する従来の範囲を維持するため、過去の別月の要確認行でも売上目標全体が保留になる場合がある。個別の訂正は根拠となる納付日と金額を確認し、別途承認を得て行う。今回、実顧客の登録状況を調査・変更していない。

## 根拠と限界

[町田市「申告から納付までのながれ」](https://www.city.machida.tokyo.jp/kurashi/tax/kotei/shokyaku/shokyaku02.html)で申告・価格決定・納税通知・納付が別の段階であることを確認。町田市固有の納付月を他自治体へ適用しない。[国税庁の消費税](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shohi/6137.htm)、[福岡県の法人事業税](https://www.pref.fukuoka.lg.jp/contents/hojin-jigyozei.html)、[福岡市の法人市民税](https://www.city.fukuoka.lg.jp/zaisei/shisanzei/life/002.html)も既存申告納付の区別を確認する参考とした。期限計算や個別特例を新たに判定する変更ではない。納税通知書の取込や固定資産税の分割納付予定の新規実装は含まない。

過去の登録の個別確認/訂正、P02/P03の次の行動・不足入力、P05/P06の選択欄・用語、P04/P07の入力定義と例示は残課題。「初めて使う人が単独で理解できる」という利用者受入はまだ未達。横断分析と書類整理連携は次期計画のまま。
