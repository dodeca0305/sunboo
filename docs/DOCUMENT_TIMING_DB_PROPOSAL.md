# 書類の対象時期を保存する限定DB変更案（未承認・未適用）

2026-11-06。現行本番のworkspace_documentsはcompany_id、document_type、status、updated_atだけで、会社/書類種類につき1行。updated_atは状態を書き換えた日時であり、申告の対象期間や証明書の発行日には使えない。会社の決算月・現在年・別の決算実績から対象時期を推測することもしない。

今回の表示修正では「会社の書類」と「対象期間/発行日：未記録」を示すところまでとする。実際の時期を入力して次回も表示するには、以下のDB変更の承認が必要。

## 承認をお願いする範囲

既存のworkspace_documentsに、任意の日付列3つと期間の整合性CHECKを1つ追加する。

| 列 | 型 | 用途 |
| --- | --- | --- |
| period_start | date / NULL可 | 申告書・納付書が対象とする期間の初日 |
| period_end | date / NULL可 | 同じ期間の末日 |
| document_date | date / NULL可 | 登記簿謄本の発行日、定款の作成・変更日など、対象書類に書かれた日付 |

書類の種類ごとに、期間または日付の意味を画面で説明する。申告書の対象期間と、提出日・登録日を混ぜない。既存の行は3列ともNULLで保持し、未記録を今年分へ自動変換しない。状態を変えただけで時期を消さない。

```sql
-- 承認後、今回だけのマイグレーションを新規作成して限定適用する案。
-- このファイルは提案であり、実行していない。
ALTER TABLE public.workspace_documents
  ADD COLUMN period_start date,
  ADD COLUMN period_end date,
  ADD COLUMN document_date date,
  ADD CONSTRAINT workspace_documents_period_pair_check CHECK (
    (period_start IS NULL AND period_end IS NULL)
    OR
    (period_start IS NOT NULL AND period_end IS NOT NULL
      AND period_start <= period_end)
  );
```

テーブル追加・既存列の変更・DB関数追加/変更・権限/既存RLSポリシー変更・課金は対象外。既存SQLの一括適用、実運用行の更新/削除、過去年の推定入力もしない。

## 保存と失敗時の保護

- 1回の保存で、対象1行の状態・時期をまとめて保存する。複数の独立保存に分けない。
- 既存updated_atトリガーを利用。取得時のupdated_atを精度を落とさない文字列のまま比較し、一致する行だけをUPDATEする。0行なら同時編集として止め、上書きしない。新規行はINSERTし、既存主キーとの競合では上書きしない。
- 登録済みデータの取得失敗では編集を止め、空の時期を上書きしない。実際の未記録は入力可能にする。
- 送信前に、利用者・会社・書類種類ごとの保存予定と保存前の値をブラウザーへ記録する。通信結果不明は成功とせず、再読込後も保存結果を再取得・照合するまで再送しない。
- 再取得値が保存予定と一致すれば確認済みとする。保存前のままなら、確認した同じ内容だけを本人の操作で再試行可能とする。別の更新があれば競合として停止する。
- 他会社/権限外の取得・保存は既存のアクセス制御で拒否する。今回アクセス範囲を広げない。

同時編集・通信例外/応答喪失後の復旧・正常未記録・部分的な期間の拒否・他会社/権限拒否をローカル合成データで確認する。本番は承認された列とCHECKだけの限定適用と架空会社23の読み取り確認に限定する。

## 復旧

適用前に対象表の定義・制約・トリガー・権限とマイグレーション状態を保存する。アプリ側の問題なら旧画面へ戻して新しい列は保持し、入力された時期を消さない。列を削除する復旧は自動実行しない。保存データが生じた後に削除が必要なら、先に退避し、追加の承認を受ける。

## 今回含めないこと

過年度の複数書類や複数バージョンの保存、ファイル添付、共有リンクへの新たな公開、提出代行、書類の有効性/期限の自動判定は含めない。現行どおり書類種類ごとに1つの現在の記録を扱う。これ以上のDB関数/権限等が必要と判明した場合は、その追加分だけ別案を示して止める。
