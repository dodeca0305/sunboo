# AI分担と利用量を抑える運用

## 担当

| 担当 | 作業 | 次に渡すもの |
| --- | --- | --- |
| Codex | 試用感想の分類、要件/対象/完了条件の整理 | current-task.jsonの1件 |
| Claude Code | 指定実装、対象試験、必要なビルド | 差分とLAST_RESULT.md |
| Codex | 差分レビュー、証跡確認、PR/CI/マージ、本番読み取り | 短い完了報告/点検記録 |
| Gemini | 割り当てられた公開一次情報調査/説明文案 | URLと根拠、コードは変更しない |
| Muse | 製品/用途確認後に割当 | まだ接続/起動しない |

Claude Codeに本番接続を渡さない。ローカルMCPは起動補助で空に限定する。
これは全ファイル/通信の強制隔離ではない。共通制約と通常の権限確認を維持する。

## 1件の開始

1. Codexが最新main/PR/状態を一度確認し、未コミット変更を保護する。
2. codex/ブランチを作り、current-task.jsonを更新する。実装前HEADをbaseShaに書く。
   filesは狭い範囲、acceptanceは期待する振る舞い、checksは必要な合成試験/ビルド。
   statusは依頼が確定するまでidle、確定後にready。同じ課題の実装担当は1つ。
3. `python3 scripts/claude_task.py --dry-run`で依頼/基点/作業状態を確認する。
4. `python3 scripts/claude_task.py`でClaude Codeを起動する。通常はSonnet/medium、
   既存のclaude.aiログインだけを使う。API/provider指定や認証不明では起動しない。
5. 最初は本人の画面で`/usage`を確認し、終了時と比較する。追加利用枠の課金設定も確認する。
   この補助はアカウントの課金上限を変更せず、既存の追加課金設定をOFFにするものでもない。
   初回のモデル依頼は、追加課金を使わない設定を確認してから行う。

現在は製品実装の未割当なのでidle。接続/認証/補助の検査だけを行い、実装を空起動しない。
`--check`はCLIと認証だけを確認し、モデルへ依頼を送らない。OSの資格情報へアクセスできない
実行環境では未認証表示になるため、必要なOSアクセスまたは本人のターミナルで再確認する。

## 節約と品質を両立する区切り

- 1件1セッション。引き継ぎは依頼/基点/対象/完了条件/結果だけ。全会話や全docsを添付しない。
- 途中で担当を変える場合は、変更と証跡を保存し、前担当を停止してから交代する。
- 小さい表示修正は数項目をまとめて1PR。重大な破損/権限漏れは単独で優先対応する。
- 既存の合成試験を使い、関連範囲を一度検証する。全文ログはファイルに置く。
- Codexは同じコミットの成功試験を再実行せず、差分/証跡とCIを確認。
  新しい変更/失敗/未解決の懸念がある場合に限り必要箇所を再検証する。
- Claudeは同じ原因の失敗が2回、または探索範囲が拡大する前に現在の証拠を返す。
- CIは完了時の結果を中心に確認し、短い間隔で何度も確認しない。既存CIチェックは維持する。
- 並列AI/子エージェント/自動レビュー/定期実行は初期状態では使わない。
- 終了時にClaudeがLAST_RESULT.mdを記入。Codexが確認後、依頼をidleへ戻す。
- 製品のmain/制約を変えた場合だけCURRENT_HANDOFF.mdを更新し、長い履歴は常時読まない。

## 上限の扱い

Sonnet/mediumや文脈の縮小は利用量を抑えるための運用で、トークン数/購読枠の絶対上限ではない。
`--max-turns`は非対話モードだけの回数制限、`--max-budget-usd`はAPI向けの制限であり、
購読枠の上限設定の代わりにはしない。APIへの自動切替/新規課金/利用枠購入はしない。
削減率は未測定。最初の1件で開始/終了の`/usage`、担当モデル、所要時間、再試行回数を記録する。
