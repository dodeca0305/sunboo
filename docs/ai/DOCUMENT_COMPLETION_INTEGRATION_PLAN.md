# 書類準備から完了まで：本番組込み案

2026-11-15。提案段階。実装・本番反映の承認とは扱わない。

## 根拠と初回範囲

利用者は単独HTMLで書類準備→提出後2確認→明示完了まで試用済み。CUAで完了画面を確認し、一連の使いやすさへの回答は「大丈夫」。
初回は編集可能な会社別年間ロードマップの償却資産申告（DEPRECIABLE_ASSET_TAX_RETURN）のみ。他手続き、公開・共有の読み取り画面は従来の案内を維持する。

## 利用者の流れ

1. 対象カードに、既存の必要書類データから実際のチェック欄を表示する。見本の書類2つを固定で本番へ持ち込まない。必須書類だけを準備条件にし、任意は条件外。事前準備・提出前チェックは既存の案内を維持する。
2. 必須書類がすべて揃ったら「準備できました」と「提出後の確認へ」を表示する。準備完了で手続き状態は更新しない。
3. 既存の条件「申告書を提出した」「受付を確認し、控えを保管した」の2つを確認する。全条件が揃うまで「完了にする」を無効にする。
4. 「完了にする」で既存の手続き状態保存処理へdoneを1回送信する。会社・手続き・期限の一致する保存結果を確認した後、既存どおり会社ホームへ戻し、完了通知を表示する。

## 保存するもの・しないもの

- 保存するのは既存の手続き状態だけ。workspace_procedure_statusesの会社ID・手続きID・期限単位の保存と、既存の応答確認・結果不明時の再取得を再利用する。
- 書類チェックと提出後確認は、その画面で開いている間だけの確認。画面内で前の段階へ戻っても保持するが、再読込・画面移動では消える。この制約を短く表示する。画面/会社/手続き/期限をまたいで引き継がない。
- 既存の書類管理の準備状況は会社・書類名ごとの共通記録であり、年度別の提出記録ではない。そこから今回のチェックを自動入力したり、今回の操作で共通記録を書き換えたりしない。
- チェック内容の永続保存、提出日時、証憑の登録、監査記録は初回範囲外。必要になれば会社・手続き・期限・書類を区別する保存案を別途提示する。
- 現時点のコード確認ではDB構造・DB関数・権限・課金の追加は不要と見込む。実装で必要になれば止めて具体案を示し、追加承認を得る。

## 既存機能との接続・例外

- 対象手続きの対応状況で「完了」を選んだ場合も同じ確認導線へ進め、即保存で確認を迂回させない。未着手・進行中・保留の既存操作は維持する。
- すでに保存済みの完了はそのまま表示する。新しいチェックがないことを理由に未完了へ戻さない。既存の完了取消通知の動作を維持し、戻る・チェック解除を保存済み完了の取消として扱わない。
- 未保存の確認中に書類チェックを外したら提出後の確認を消し、再確認が必要な状態にする。確認だけでは自動完了しない。
- 書類データが欠ける/取得に失敗する場合は「書類なし」「準備済み」と判定しない。初回対象で必要書類が0件または必須0件の場合も空集合の全チェック扱いをせず、案内を表示して新しい完了操作を保留する。取得元で欠落と正常な空を区別できるか実装前に限定確認する。
- 保存中の連打を防ぐ。保存結果不明なら完了を表示せず再送を止め、既存の再取得で確認する。取得失敗を未着手等に置き換えない。
- 状態の再取得で別画面からの変更が判明した場合は現在の保存状態を優先する。書類条件や対象会社・期限が変わった場合は古いチェックを流用しない。
- このチェックは本人の確認補助であり、税務上の適否判定や提出先の受付検証を行うものではない。
