# 年間ロードマップの手続き状態取得・保存保護

起点main: `3f4e4d7`（PR #145）。PR #143の納税予定保護を維持し、手続き状態の編集と完了/Undoの確認を保護する。

## 取得と表示

`loadWorkspaceProcedureStatusesForEditing` は会社IDで絞り込んで1回だけ取得し、会社・手続き・出現回・状態を検証する。取得失敗や不正な応答を空Mapへ置き換えない。正常な0行は従来どおり未登録として操作可能。既存の完了/進行中/保留/明示的な未着手を保持する。

取得不可ならステータス・未着手の代替表示・状態変更を出さず、エラーと再読み込みを表示。未取得の状態を含むExcel/PDFも出力させない。納税予定が正常取得できていれば、そちらの入力・保存は維持する。

共用contextに状態取得を省略するオプションを追加し、このページだけ専用loaderへ置き換える。ロードマップ計算エンジン・他の共用呼び出し元は変更しない。状態取得とロードマップ/納税予定取得は並列に行う。

## 保存と応答喪失

1行のupsertなのでDBトランザクション関数や新しい権限は不要。保存時は返却行の会社ID・手続きID・出現回・状態を照合し、確認前の楽観的な表示変更は行わない。

送信前に会社別のセッション記録を確保し、保存中・結果不明時の状態変更を止める。error/通信例外でもfinallyで処理中表示を解除する。結果不明の記録はページ再読み込みで消さず、「保存結果を確認」から現在の全状態を再取得する。取得失敗なら停止を維持する。同じキーの行が存在して送信状態と一致する場合だけ保存確認とし、別状態/不存在は現在値を表示して操作を再開する。不存在を未着手の保存成功とは扱わない。自動再送しない。

完了時は確認後にだけ通知・ホーム遷移を行い、Undoの直前状態を保持する。Undoも同じ保存確認を使い、結果不明中は成功の完了表示を出さず、ロードマップでの再取得へ案内する。

サーバー再取得では状態だけを同期し、同じ会社の未保存の税額ドラフトを状態変更による再マウントで消さない。予定税額の保存処理そのものは変更しない。

## 影響と残課題

DB構造・権限・既存SQLは変更しない。ホーム/書類等の共用read loaderの取得失敗表示は今回の対象外。窓口・決算実績の取得失敗対策も残る。失敗した状態を保存済みと報告せず、CI/マージ/本番確認/原状復元の最終結果はPRで記録する。
